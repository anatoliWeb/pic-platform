# Бібліотека IR Receiver

## Опис

`ir_receiver` — легка неблокуюча бібліотека декодування ІЧ сигналів з початковою підтримкою NEC.
Архітектура відокремлює захоплення таймінгів від протокольного декодера, тому легко додавати нові протоколи.

## Публічний API

- `ir_receiver_init()`
- `ir_receiver_update()`
- `ir_receiver_available()`
- `ir_receiver_read()`
- `ir_receiver_clear()`

## Підтримувані протоколи

- NEC (поточна реалізація)
- Архітектура підготовлена для:
  - RC5
  - Sony SIRC
  - інших протоколів

## Нотатки по архітектурі декодера

- Захоплення edge/timing зроблено універсально.
- Протокол вибирається через `config.protocol`.
- NEC декодер використовує модель періодів між falling edges:
  - виявлення leader
  - виявлення repeat frame
  - декодування 32-бітного кадру
  - перевірка інверсійних байтів команди

## NEC таймінги (огляд)

Типовий NEC кадр (після демодулятора, active-low marks):

- Leader mark + space
- 32 data біти
- опційний repeat frame

Класифікація бітів виконується по діапазонах періодів з допусками.

## Repeat frame

Повтор кнопки позначається:

- `frame.repeat = 1`
- протоколом `IR_PROTOCOL_NEC`

## Timeout і захист від помилок

- Неблокуюча модель: немає очікування завершення кадру в циклі.
- Неповні/биті кадри скидаються по timeout.
- Статуси помилок включають:
  - invalid timing
  - incomplete frame
  - timeout reset
  - checksum/inversion mismatch

## Підключення

- Вихід IR receiver модуля (демодульований TTL) підключити на input MCU.
- Більшість модулів мають idle HIGH і LOW під час IR mark.
- Додайте стабільне живлення і розв'язуючі конденсатори біля модуля.

## Рекомендації по інтеграції

- Викликайте `ir_receiver_update()` з:
  - швидкого main loop
  - scheduler task
  - timer-driven update
- `sample_period_us` має бути достатньо малим для точного розрізнення таймінгів.

## Залежності

- `core/*`
- `drivers/gpio`
- таймер/interrupt інфраструктура опціонально з боку application scheduling
