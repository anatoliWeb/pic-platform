# SSD1306 Display Library

## Description

`ssd1306` is a reusable monochrome graphics display library for SSD1306 OLED modules.
It is designed as a backend-ready display component for `display_framework`.

## Public API

- `ssd1306_init()`
- `ssd1306_clear()`
- `ssd1306_update()`
- `ssd1306_draw_pixel()`
- `ssd1306_draw_char()`
- `ssd1306_draw_string()`
- `ssd1306_draw_line()` (optional)
- `ssd1306_draw_rect()` (optional)
- `ssd1306_draw_bitmap()` (optional)
- `ssd1306_get_display_driver()`

## Framebuffer Architecture

- Internal 1-bit framebuffer is used.
- Max buffer size is 1024 bytes (128x64).
- SSD1306 page layout is used (`y/8` pages, horizontal columns).
- Draw calls update RAM only.
- `ssd1306_update()` flushes framebuffer to OLED.

This avoids slow per-pixel I2C writes.

## Supported Display Sizes

- 128x64
- 128x32

Prepared for future SH1106 compatibility in architecture.

## Transport Notes

- I2C mode is implemented and required for current backend.
- SPI mode is reserved in API for future extension.
- Typical I2C addresses: `0x3C` or `0x3D`.

## Font Support

- Built-in 5x7 ASCII font (`0x20..0x7F`).
- Lightweight fixed-width text rendering.

## display_framework Integration

Use adapter function:

- `ssd1306_get_display_driver()`

It fills `display_driver_t` callbacks so `display_init()` can use SSD1306 as unified backend.

## Memory Usage

- 128x64: 1024 bytes framebuffer
- 128x32: 512 bytes active area (still using internal max array for portability)

## Limitations

- Monochrome 1-bit rendering only
- No anti-aliasing
- No variable fonts in current implementation

## Dependencies

- `core/*`
- `drivers/communication/i2c`
- `libraries/display/display_framework`
