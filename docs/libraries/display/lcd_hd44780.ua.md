# LCD HD44780 Драйвер

## Опис

Драйвер LCD HD44780 з двома транспортами:

- GPIO 4-бітний режим (`lcd_*`).
- PCF8574 I2C backpack (`lcd_i2c_*`).

Обидва надають ініціалізацію, керування курсором і вивід тексту.

Правила project-wide compile-time mapping описано в `docs/configuration.ua.md`.

## API

### GPIO транспорт

- `lcd_init_pins()`
- `lcd_init()`
- `lcd_clear()`
- `lcd_set_cursor()`
- `lcd_write_char()`
- `lcd_write_string()`

### I2C транспорт

- `lcd_i2c_init(i2c_addr, i2c_clock_hz)` — повна ініціалізація (I2C + LCD, підсвітка увімкнена); готовність після успіху.
- `lcd_i2c_attach(i2c_addr)` — прив'язка до вже ініціалізованої I2C-шини. Лише
  probe: ніколи не викликає `i2c_init()`, не виконує послідовність ініціалізації
  HD44780 і не очищає дисплей. Прив'язка фіксується лише після успішного
  probe. Після нього викличте `lcd_i2c_controller_init()`.
- `lcd_i2c_controller_init()` — лише послідовність ініціалізації HD44780 для
  адреси, прив'язаної через `init()` або `attach()`; повертає
  `LCD_I2C_NOT_INITIALIZED`, якщо адресу не прив'язано.
- `lcd_i2c_probe(i2c_addr)` — перевірка наявності пристрою без side effects для
  стану модуля.
- `lcd_i2c_last_status()` — статус останньої операції.
- `lcd_i2c_is_ready()` — прапорець готовності (скидається при NACK).
- `lcd_i2c_clear()`
- `lcd_i2c_home()`
- `lcd_i2c_set_cursor(row, col)`
- `lcd_i2c_write_char(c)`
- `lcd_i2c_write_string(str)`
- `lcd_i2c_backlight(on)`

Статуси: `LCD_I2C_OK`, `LCD_I2C_INVALID_ARGUMENT`, `LCD_I2C_NOT_INITIALIZED`,
`LCD_I2C_NO_ACK`.

Адреса - 7-бітна (без маскування); адреса `0x00` та адреси вище `0x7F`
відхиляються. NACK обриває поточну операцію (жодних подальших I2C-транзакцій),
скидає прапорець готовності і зберігає `NO_ACK`, доки не спрацює явне
відновлення. `lcd_i2c_write_string()` зупиняється на першому failed символі.
Операції виводу (`clear`, `home`, курсор, текст, підсвітка) відмовляються
торкатися шини, поки контролер не буде ініціалізований знову через
`lcd_i2c_init()` або `lcd_i2c_controller_init()`. Розведення PCF8574
налаштовується на етапі компіляції через `LCD_I2C_PIN_RS/RW/EN/BL` та
`LCD_I2C_DATA_SHIFT` (за замовчуванням - типова backpack-плата: P0=RS, P1=RW,
P2=EN, P3=Підсвітка, P4..P7=D4..D7); некоректне розведення не проходить збірку.

## Приклад

### GPIO

```c
lcd_init_pins(&PORTD, &TRISD, &PORTC, &TRISC, 0u, &PORTC, &TRISC, 1u, 4u, 5u, 6u, 7u);
lcd_init();
lcd_set_cursor(0u, 0u);
lcd_write_string("System OK");
```

### I2C

```c
if (lcd_i2c_init(0x27u, 100000u) != LCD_I2C_OK) {
    /* backpack відсутній або підключений неправильно */
}
lcd_i2c_set_cursor(0u, 0u);
lcd_i2c_write_string("System OK");
```

## Особливості

- GPIO транспорт працює у 4-бітному режимі передачі.
- I2C транспорт керує PCF8574 backpack через спільний I2C master.
- Таймінги команд/даних залежать від шару delay.
- `lcd_i2c_probe()` лише діагностичний; `lcd_i2c_attach()` володіє bind.
