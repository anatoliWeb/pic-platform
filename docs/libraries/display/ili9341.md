# ILI9341 TFT Library

## Description

`ili9341` is a reusable SPI color TFT backend for pic-platform.
It follows the same lightweight direct-render architecture as `st7735` and integrates with `graphics`, `bitmap`, `sprite_buffer`, and `display_framework`.

## Public API

- `ili9341_init()`
- `ili9341_clear()`
- `ili9341_update()`
- `ili9341_draw_pixel()`
- `ili9341_fill_rect()`
- `ili9341_set_rotation()`
- `ili9341_draw_bitmap()` (optional)
- `ili9341_blit_sprite()` (optional)
- `ili9341_set_window()` (optional)
- `ili9341_get_display_driver()`

## Framebuffer / Update Architecture

- Default mode is direct rendering (no full-screen framebuffer allocation).
- Pixel and rectangle writes use SPI windowed transfers.
- `ili9341_update()` is a no-op in direct mode.
- Prepared for partial update and dirty-region optimization at higher layers.

## Display Model

- Native size: 240x320
- RGB565 color format
- Rotation: 0/90/180/270 with MADCTL remap

## SPI Notes

- SPI transport only
- Uses configured control lines via GPIO:
  - CS
  - DC
  - RESET
- Uses existing `drivers/communication/spi` and `drivers/gpio` only.

## Graphics Integration Notes

- `display_framework` char rendering is routed through `graphics_draw_char()` with callback pixel output.
- Bitmap and sprite helpers are implemented as thin wrappers over existing `bitmap_t` and `sprite_t` data.
- Primitive rendering is intentionally lightweight for PIC targets.

## ST7735 vs ILI9341 Notes

- ILI9341 targets larger panel (240x320).
- Command set and init sequence differ.
- Shared architecture: direct render, window writes, RGB565 helpers, rotation model.

## Memory / Performance

- No dynamic memory
- Integer-only logic
- Small RAM footprint
- Suitable for PIC devices where full TFT framebuffer is too heavy

## Dependencies

- `core/*`
- `drivers/communication/spi`
- `drivers/gpio`
- `libraries/display/graphics`
- `libraries/display/display_framework`
- `libraries/ui/sprite_buffer`
