# SH1106 Display Library

## Description

`sh1106` is a reusable monochrome OLED display library for SH1106 controllers.
It reuses the shared `graphics` and `bitmap` infrastructure and integrates with `display_framework`.

## Public API

- `sh1106_init()`
- `sh1106_clear()`
- `sh1106_update()`
- `sh1106_draw_pixel()`
- `sh1106_draw_char()`
- `sh1106_draw_string()`
- `sh1106_draw_line()` (optional)
- `sh1106_draw_rect()` (optional)
- `sh1106_get_display_driver()`

## SH1106 Offset Handling Notes

SH1106 has internal 132-column RAM while most modules expose 128 columns.
This library uses configurable `x_offset` (default `2`) to align framebuffer column 0
with visible display column 0.

Per page update:

- set page address (`0xB0 + page`)
- set lower column nibble with offset
- set higher column nibble with offset
- stream 128 bytes of visible framebuffer data

## Framebuffer Architecture

- Internal 1-bit framebuffer: `128 x 64 / 8 = 1024` bytes
- Page-oriented memory layout compatible with graphics core
- Draw calls modify RAM only
- `sh1106_update()` flushes framebuffer to display

## Graphics Integration Notes

Rendering is delegated to shared `graphics_t` context:

- `sh1106_draw_pixel()` -> `graphics_draw_pixel()`
- `sh1106_draw_char()` -> `graphics_draw_char()`
- `sh1106_draw_string()` -> `graphics_draw_string()`
- line/rect wrappers use graphics primitives

No duplicated rendering algorithms in this backend.

## Transport Support

- I2C mode implemented (required)
- SPI mode reserved in API for future extension

## display_framework Integration

`sh1106_get_display_driver()` provides adapter callbacks for:

- clear
- update
- draw_pixel
- draw_char

## SSD1306 Differences

- SH1106 requires explicit column offset handling
- RAM width is 132, visible panel usually 128
- Command sequence differs from SSD1306 initialization

## Dependencies

- `core/*`
- `drivers/communication/i2c`
- `libraries/display/graphics`
- `libraries/display/display_framework`
