# Бібліотека SH1106

## Опис

`sh1106` — універсальна бібліотека монохромних OLED-дисплеїв на контролері SH1106.
Бібліотека повторно використовує спільну інфраструктуру `graphics` і `bitmap` та інтегрується з `display_framework`.

## Публічний API

- `sh1106_init()`
- `sh1106_clear()`
- `sh1106_update()`
- `sh1106_draw_pixel()`
- `sh1106_draw_char()`
- `sh1106_draw_string()`
- `sh1106_draw_line()` (опційно)
- `sh1106_draw_rect()` (опційно)
- `sh1106_get_display_driver()`

## Нотатки по SH1106 Offset

SH1106 має внутрішню RAM на 132 колонки, а більшість модулів показують 128.
Бібліотека використовує налаштовуваний `x_offset` (за замовчуванням `2`) для вирівнювання
колонки 0 framebuffer з видимою колонкою 0 дисплея.

Для кожної сторінки update:

- виставляється адреса сторінки (`0xB0 + page`)
- виставляється молодший nibble колонки з offset
- виставляється старший nibble колонки з offset
- передаються 128 байтів видимого framebuffer

## Архітектура Framebuffer

- Внутрішній 1-бітний framebuffer: `128 x 64 / 8 = 1024` байти
- Сторінкова розкладка сумісна з graphics core
- Усі draw-операції змінюють лише RAM
- `sh1106_update()` виконує flush у дисплей

## Нотатки по Інтеграції з Graphics

Рендеринг делегується через спільний `graphics_t`:

- `sh1106_draw_pixel()` -> `graphics_draw_pixel()`
- `sh1106_draw_char()` -> `graphics_draw_char()`
- `sh1106_draw_string()` -> `graphics_draw_string()`
- wrappers для line/rect використовують примітиви graphics

Дублювання алгоритмів рендерингу відсутнє.

## Підтримка Транспорту

- I2C режим реалізовано (обов'язковий)
- SPI режим залишено в API як підготовка

## Інтеграція з display_framework

`sh1106_get_display_driver()` надає callbacks для:

- clear
- update
- draw_pixel
- draw_char

## Відмінності від SSD1306

- SH1106 вимагає обробки X-offset
- RAM ширина 132, видима область зазвичай 128
- Послідовність ініціалізації відрізняється від SSD1306
