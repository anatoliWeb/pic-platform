# ST7735 TFT Library

## Description

`st7735` is a reusable SPI color TFT backend for pic-platform.
It is display-agnostic at the rendering API level and integrates with `graphics`, `bitmap`, `sprite_buffer`, and `display_framework`.

## Public API

- `st7735_init()`
- `st7735_clear()`
- `st7735_update()`
- `st7735_draw_pixel()`
- `st7735_fill_rect()`
- `st7735_set_rotation()`
- `st7735_draw_bitmap()` (optional)
- `st7735_blit_sprite()` (optional)
- `st7735_set_window()` (optional)
- `st7735_get_display_driver()`

## Framebuffer / Update Architecture

- Default mode is **direct rendering** (no full-screen framebuffer allocation).
- `st7735_draw_pixel()` and `st7735_fill_rect()` write through SPI to selected window.
- `st7735_update()` is a no-op in direct mode.
- Architecture is prepared for partial-buffer and dirty-region upgrades.

## Color Model

- RGB565 format
- Helper macro: `ST7735_COLOR565(r,g,b)`
- Common colors are defined (`BLACK`, `WHITE`, `RED`, etc.)

## Transport and Control Lines

- SPI transport only
- Uses existing drivers:
  - `drivers/communication/spi`
  - `drivers/gpio`
- Configurable pins:
  - `CS`, `DC`, `RESET`

## Rotation

Supported rotations:

- `ST7735_ROT_0`
- `ST7735_ROT_90`
- `ST7735_ROT_180`
- `ST7735_ROT_270`

MADCTL is updated internally and logical width/height are adjusted.

## Graphics Integration Notes

- Backend reuses graphics core for text (`graphics_draw_char` through callback context).
- Bitmap and sprite helpers are provided without hardware duplication in upper layers.
- `st7735_get_display_driver()` exposes adapter callbacks for display framework.

## Memory / Performance Notes

- No dynamic memory
- Integer-only logic
- Small RAM footprint (PIC-friendly)
- Suitable for primitive UI and direct rendering workflows

## Dependencies

- `core/*`
- `drivers/communication/spi`
- `drivers/gpio`
- `libraries/display/graphics`
- `libraries/display/display_framework`
- `libraries/ui/sprite_buffer` (optional helpers)
