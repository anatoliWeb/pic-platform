# RS485 Driver

## Description

RS485 protocol layer built on top of UART.
Provides direction control (DE/RE), byte transfer, and framed data exchange.

## API

- `rs485_init()` — initialize direction control pin, start in RX mode
- `rs485_set_tx()` — switch to transmit mode
- `rs485_set_rx()` — switch to receive mode
- `rs485_send_byte()` — send one byte (direction must be TX)
- `rs485_read_byte()` — read one byte (direction must be RX)
- `rs485_send_frame()` — blocking framed send with CRC16 Modbus
- `rs485_receive_frame()` — blocking framed receive with CRC validation
- `rs485_crc8()` — Dallas CRC8 helper

## Blocking behavior

- `rs485_send_frame()` blocks until all bytes are shifted out via UART. The XC8 wrapper waits for the TRMT bit to ensure the final byte (including stop bit) has physically left the TX pin before switching direction.
- `rs485_receive_frame()` blocks with a timeout while waiting for each byte. If no data arrives within `RS485_TIMEOUT_TICKS`, the function returns 0.
- Direction switching includes guard delays (`DRV_DELAY_US(50u)`) before the first byte and after the final bit to allow the MAX487 transceiver to settle.

## RX restore

- `rs485_receive_frame()` calls `rs485_set_rx()` at the start to ensure the transceiver is in receive mode.
- On timeout or CRC error, the function returns 0 but does not change the direction pin; the caller should call `rs485_set_rx()` if needed before the next receive attempt.
- After a successful `rs485_send_frame()`, the transceiver is automatically returned to RX mode.

## Final byte preservation

- All compiler paths (XC8, C18, and shared fallback) include `rs485_wait_tx_complete()` which polls the PIC18 `TXSTAbits.TRMT` bit until the UART shift register is fully empty.
- After TRMT confirms the last stop bit has physically left the TX pin, a 50 us guard delay allows the MAX487 transceiver to settle before direction switching.
- The TRMT bit is a PIC18 hardware register available across all supported compilers (XC8 and C18), so the final-byte guarantee applies uniformly.

## Error recovery

- On any timeout during receive, the function returns 0 (no valid frame).
- CRC mismatch returns 0.
- The caller is responsible for retrying or switching direction as needed.

## Example

```c
uint8_t tx_data[3] = {0x10u, 0x20u, 0x30u};
uint8_t rx_data[16];

rs485_init(&PORTB, &TRISB, 2u);
rs485_send_frame(tx_data, 3u);                     // blocking send
len = rs485_receive_frame(rx_data, sizeof(rx_data)); // blocking receive
```

## Notes

- TX/RX direction is controlled by DE/RE pin via GPIO.
- Frame integrity is validated by internal CRC check (current API exposes `rs485_crc8`).
- The driver is single-instance (static globals for direction pin).
- No non-blocking API is provided; the blocking model is intentional for simple half-duplex protocols.
