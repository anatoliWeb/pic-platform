# RS485 Driver

## Description

RS485 protocol layer built on top of UART.
Provides direction control (DE/RE), byte transfer, and framed data exchange.

## API

- `rs485_init()` — initialize direction control pin, start in RX mode
- `rs485_set_tx()` — switch to transmit mode
- `rs485_set_rx()` — switch to receive mode
- `rs485_send_byte()` — send one byte (direction must be TX)
- `rs485_read_byte()` — read one byte (direction must be RX)
- `rs485_send_frame()` — blocking framed send with CRC16 Modbus
- `rs485_receive_frame()` — blocking framed receive with CRC validation
- `rs485_crc8()` — Dallas CRC8 helper

## Blocking behavior

- `rs485_send_frame()` blocks until all bytes are shifted out via UART. It uses a bounded TRMT polling loop (`RS485_TX_COMPLETE_TIMEOUT = 200` iterations). If the timeout expires (UART not initialized or hardware fault), the function returns 0 and restores RX mode. On success it returns 1 after a 50 us settling delay.
- `rs485_receive_frame()` blocks with a timeout while waiting for each byte. If no data arrives within `RS485_TIMEOUT_TICKS`, the function returns 0.
- Direction switching includes guard delays (`DRV_DELAY_US(50u)`) before the first byte and after the final bit (settling delay, not final-byte proof) to allow the MAX487 transceiver to settle.

## RX restore

- `rs485_send_frame()` always calls `rs485_set_rx()` before returning — line never stays in TX after the public API returns, regardless of success or timeout.
- `rs485_receive_frame()` calls `rs485_set_rx()` at the start to ensure the transceiver is in receive mode.
- On timeout or CRC error, the function returns 0 but does not change the direction pin; the caller should call `rs485_set_rx()` if needed before the next receive attempt.

## Final byte preservation

- **XC8 wrapper** (verified): `rs485_wait_tx_complete()` polls `TXSTAbits.TRMT` with a bounded timeout of 200 iterations. TRMT becomes 1 within one byte time (~1ms at 9600 baud). On success, a 50 us guard delay allows the MAX487 transceiver to settle before direction switching. On timeout, the function returns 0 and RX is still restored.
- **C18 wrapper** (not build-verified): identical bounded TRMT polling. The C18 compiler provides SFR access automatically based on the target device. Structurally identical to other verified C18 drivers (e.g. `uart.c`). C18 toolchain was not available for build verification.
- **Shared fallback** (`#else` block): unreachable dead code. `core/compiler.h` requires `DRV_COMPILER_XC8` or `DRV_COMPILER_C18`, otherwise compilation fails with `#error`. Updated for consistency but never executed.

## Error recovery

- TX-complete timeout: `rs485_send_frame()` returns 0, RX is restored. Repeated send after timeout works.
- `uart_write_byte()` has no error return (hardware limitation). The only detectable failure is TX-complete timeout.
- On receive timeout or CRC error, the function returns 0. The caller is responsible for retrying or switching direction.

## Example

```c
uint8_t tx_data[3] = {0x10u, 0x20u, 0x30u};
uint8_t rx_data[16];

rs485_init(&PORTB, &TRISB, 2u);
rs485_send_frame(tx_data, 3u);                     // blocking send
len = rs485_receive_frame(rx_data, sizeof(rx_data)); // blocking receive
```

## Notes

- TX/RX direction is controlled by DE/RE pin via GPIO.
- Frame integrity is validated by internal CRC check (current API exposes `rs485_crc8`).
- The driver is single-instance (static globals for direction pin).
- No non-blocking API is provided; the blocking model is intentional for simple half-duplex protocols.
