# RS485 Драйвер

## Опис

RS485 протокольний шар поверх UART.
Надає керування напрямком (DE/RE), побайтовий обмін і обмін кадрами.

## API

- `rs485_init()` — ініціалізація піна напрямку, старт у режимі RX
- `rs485_set_tx()` — переключення в режим передачі
- `rs485_set_rx()` — переключення в режим прийому
- `rs485_send_byte()` — відправка одного байту (напрямок має бути TX)
- `rs485_read_byte()` — зчитування одного байту (напрямок має бути RX)
- `rs485_send_frame()` — блокуюча відправка кадру з CRC16 Modbus
- `rs485_receive_frame()` — блокуючий прийом кадру з валідацією CRC
- `rs485_crc8()` — хелпер Dallas CRC8

## Блокуюча поведінка

- `rs485_send_frame()` блокується до повного висилання всіх байтів через UART. XC8 обгортка очікує біт TRMT, щоб гарантувати, що останній байт (включаючи стоп-біт) фізично покинув пін TX перед переключенням напрямку.
- `rs485_receive_frame()` блокується з таймаутом при очікуванні кожного байту. Якщо дані не надходять протягом `RS485_TIMEOUT_TICKS`, функція повертає 0.
- Переключення напрямку включає захисні затримки (`DRV_DELAY_US(50u)`) перед першим байтом і після останнього біту для стабілізації трансивера MAX487.

## Відновлення RX

- `rs485_receive_frame()` викликає `rs485_set_rx()` на початку для гарантування режиму прийому.
- При таймауті або помилці CRC функція повертає 0, але не змінює пін напрямку; викликаючий має викликати `rs485_set_rx()` при потребі перед наступним прийомом.
- Після успішного `rs485_send_frame()` трансивер автоматично повертається в режим RX.

## Збереження останнього байту

- **XC8 обгортка** включає `rs485_wait_tx_complete()`, яка очікує `TXSTAbits.TRMT == 1` перед поверненням з `rs485_send_frame()`. Це гарантує, що останній стоп-біт повністю зсунутий.
- **C18 обгортка** та **спільна реалізація** використовують `DRV_DELAY_US(50u)` як захисну затримку після останнього байту; вони НЕ опитують TRMT. Ця фіксована затримка може бути недостатньою на низьких baud rates, де байт передається довше 50 us.
- Для PIC18F452 з XC8 завжди використовується XC8 обгортка (обирається через `#include` у спільному джерелі), тому гарантія останнього байту діє.

## Відновлення помилок

- При будь-якому таймауті під час прийому функція повертає 0 (немає валідного кадру).
- Невідповідність CRC повертає 0.
- Викликаючий відповідає за повторну спробу або переключення напрямку при потребі.

## Приклад

```c
uint8_t tx_data[3] = {0x10u, 0x20u, 0x30u};
uint8_t rx_data[16];

rs485_init(&PORTB, &TRISB, 2u);
rs485_send_frame(tx_data, 3u);                        // блокуюча відправка
len = rs485_receive_frame(rx_data, sizeof(rx_data)); // блокуючий прийом
```

## Особливості

- Керування TX/RX виконується через DE/RE пін із використанням GPIO.
- Цілісність кадру перевіряється внутрішнім CRC (у поточному API доступний `rs485_crc8`).
- Драйвер одинарний (статичні глобальні для піна напрямку).
- Неблокуючий API не надається; блокуюча модель навмисна для простих half-duplex протоколів.
