# DRIVER_GUIDELINES

> [English version](DRIVER_GUIDELINES.md)

Цей документ визначає єдиний стандарт створення драйверів у `pic-platform`.

## 1. Базові принципи

- Драйвери мають бути повторно використовуваними та портативними.
- Підтримуються обидва компілятори: MPLAB XC8 та MPLAB C18.
- Усі compiler-specific відмінності мають бути ізольовані в `core/compiler.h`.
- Драйвери не повинні містити логіку конкретного проєкту.
- Заборонено хардкодити піни, якщо вони не передані через явну конфігурацію/ініціалізацію.
- Заборонено використовувати динамічну пам'ять (`malloc` / `free`).
- Коментарі в коді мають бути короткими та англійською мовою.

## 2. Обов'язкова структура драйвера

Кожен драйвер у `/drivers/<name>/` повинен містити:

- `<name>.h`
- `<name>.c`
- `example.c`

## 3. Що заборонено

- Змінювати публічний API без вагомої причини.
- Додавати бізнес-логіку застосунку в драйвер.
- Прив'язувати драйвер до однієї плати без параметризації.

## 4. Compiler-specific код

Уся різниця між XC8/C18 має бути централізована в:

- `core/compiler.h`

У коді драйверів слід використовувати тільки уніфіковані макроси абстракції.

## 5. Стиль API

Рекомендований базовий API:

- `<driver>_init()`
- `<driver>_read()`
- `<driver>_write()`

Додаткові функції додаються лише коли цього вимагає периферія.

## 6. Правила іменування

- Файли: `lower_snake_case` (`uart.h`, `ring_buffer.c`).
- Типи: `<driver>_t`.
- Макроси/константи: `UPPER_SNAKE_CASE`.
- Публічні функції: `<driver>_<action>` (`uart_init`, `gpio_toggle`).
- Внутрішні функції у `.c`: `static`.

## 7. Правила для example.c

`example.c` має показувати мінімальний робочий сценарій:

- коректні `#include`;
- виклик `init()`;
- базове використання API в циклі або простій послідовності.

Приклади є демонстраційними і не повинні містити логіку реального продукту.
