# DRIVER_GUIDELINES

Цей документ визначає єдиний стандарт створення драйверів для PIC Platform.

## 1. Основні правила

- Писати драйвери максимально універсально.
- Підтримувати MPLAB C18 і MPLAB XC8.
- Усі compiler-specific відмінності виносити в `core/compiler.h`.
- Не змішувати драйвери з логікою конкретного проєкту.
- Не хардкодити піни без крайньої потреби.
- Коментарі в коді писати англійською.
- Не використовувати `malloc`/`free` у драйверах.

## 2. Обов'язкова структура драйвера

Кожен драйвер у `/drivers/<name>/` має містити:

- `<name>.h`
- `<name>.c`
- `example.c`

## 3. Що заборонено

- Хардкод пінів у публічному API.
- Будь-яка бізнес-логіка або логіка application-рівня.
- Жорстка залежність від одного компілятора.

## 4. Compiler-Specific Code

Уся специфіка C18/XC8 дозволена тільки у:

- `core/compiler.h`

Драйвери мають використовувати уніфіковані макроси абстракції.

## 5. API Стандарт

Рекомендована базова форма API:

- `<driver>_init()`
- `<driver>_read()`
- `<driver>_write()`

Дозволено додаткові функції, якщо вони справді потрібні для периферії.

## 6. Naming Rules

- Файли: lower_snake_case (`uart.h`, `soft_i2c.c`).
- Типи: `<driver>_t`.
- Константи/макроси: `UPPER_SNAKE_CASE`.
- Публічні функції: префікс драйвера (`uart_init`, `uart_write`).
- Приватні символи в `.c`: `static` + префікс модуля.

## 7. Example Rules

`example.c` має бути мінімальним робочим прикладом:

- Показує include драйвера.
- Показує `init()`.
- Показує базовий виклик API у циклі.
