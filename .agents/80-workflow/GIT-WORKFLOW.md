# Git Workflow

## Rules

- Check `git status` first.
- Protect dirty files that were already present.
- Do not use `git add .`.
- Do not push unless asked.
- Do not amend, rebase, or force-push unless asked.
- Make logical commits.
- Keep code, example, HEX, and docs changes separated when practical.
- Use professional commit messages.
- Show diff and stat before commit.
- End with a final status report.

## Commit message examples

- `feat(position-drive): add ADC-feedback actuator control library`
- `feat(position-drive-examples): add XC8 ADC feedback example`
- `build(position-drive): refresh production HEX artifact`
- `docs(position-drive): add runtime and debug diagrams`
- `docs(agents): add AI workflow instructions`
