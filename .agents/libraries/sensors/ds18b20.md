## Use when

- you need a DS18B20 sensor wrapper;
- you need fixed-point temperature reads;
- you need ROM search, Match ROM, or Skip ROM flows.

## Do not use when

- you need generic 1-Wire bus primitives only;
- you need a different sensor family.

## Runtime model

- Sensor driver on top of OneWire bus primitives.
- Uses ROM search and scratchpad reads.
- Returns fixed-point Celsius x10 in the temperature API.

## ISR requirements

```text
none directly; timing comes from the OneWire driver and delay helpers
```

## Resource ownership

- Shared 1-Wire bus line via the OneWire driver.
- A 4.7k pull-up on DQ is required.

## Integration recipe

1. Add the OneWire driver and CRC/delay dependencies.
2. Add the shared ds18b20 source or matching compiler wrapper.
3. Bind the OneWire pin in the project.
4. Use `ds18b20_find_first()` or `ds18b20_search()` to discover ROMs.
5. Read temperature with the addressed or Skip ROM path.

## Minimal usable example

```c
uint8_t rom[8];
int16_t temp_x10;

if (ds18b20_find_first(rom) != 0u)
{
    if (ds18b20_read_temperature_celsius(rom, &temp_x10) != 0u)
    {
    }
}
```

## Known limitations

- Depends on OneWire timing behavior.
- `ds18b20_multi_read` still has review notes in repository docs.

## Extension points

- Keep higher-level menu logic outside this library.

## Common mistakes

- Treating the module as a generic 1-Wire driver.
- Forgetting to include CRC and OneWire dependencies.

## AI decision rule

Use this library for DS18B20-specific handling. Use the OneWire driver for raw bus-level operations.
