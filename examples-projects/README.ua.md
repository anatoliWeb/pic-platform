# examples-projects

## Що таке examples-projects

`examples-projects` містить повні приклади проєктів MPLAB X для перевірки та тестування зовнішньої бібліотеки драйверів `pic-platform`.

- Це повні проєкти, а не лише окремі фрагменти коду.
- Використовується для перевірки інтеграції драйверів у реальних MPLAB-проєктах.
- Використовується для валідації сумісності з XC8 та C18.
- Приклади розділені за компілятором.

## Структура проєкту

```text
examples-projects/
├── xc8/
│   ├── blink.X/
│   ├── uart_debug.X/
│   └── ...
│
├── c18/
│   ├── blink.X/
│   ├── uart_debug.X/
│   └── ...
```

## Пояснення структури

- `xc8/` містить приклади для MPLAB XC8.
- `c18/` містить приклади для MPLAB C18.
- Кожна папка `.X` є самостійним проєктом MPLAB X.

## Важливі правила

- Не копіюйте драйвери в папки прикладів.
- Використовуйте тільки відносні шляхи.
- Проєкти мають використовувати зовнішню бібліотеку `../pic-platform`.
- Потрібні `.c` файли драйверів додавайте вручну в MPLAB X.

## Нотатки з інтеграції

- Проєкти залежать від `../pic-platform`.
- Include paths налаштовуються у властивостях MPLAB-проєкту.
- Файли реалізації драйверів (`.c`) повинні бути у **Source Files**.

## Підтримувані компілятори

- MPLAB XC8
- MPLAB C18

## Перелік прикладів

| Приклад | XC8 | C18 | Призначення |
|---|---|---|---|
| blink | `blink.X` | `blink.X` | Базова перевірка GPIO |
| uart_debug | `uart_debug.X` | `uart_debug.X` | Перевірка UART і debug-макросів |
| adc | `adc.X` | `adc.X` | Перевірка аналогового вводу |
| i2c | `i2c.X` | `i2c.X` | Перевірка I2C master |
| spi | `spi.X` | `spi.X` | Перевірка SPI передачі |
| rs485 | `rs485.X` | `rs485.X` | Перевірка RS485 поверх UART |
| ds18b20 | `ds18b20.X` | `ds18b20.X` | Інтеграція 1-Wire датчика температури |

## Інструкція збірки (MPLAB X)

1. Відкрийте потрібний `.X` проєкт у MPLAB X.
2. Оберіть цільовий MCU та програматор/відладчик.
3. Оберіть toolchain (`XC8` або `C18`) згідно папки проєкту.
4. Перевірте include paths: `../pic-platform`, `../pic-platform/core`, `../pic-platform/drivers`.
5. Перевірте наявність потрібних `.c` файлів у **Source Files**.
6. Запустіть збірку.

## Рекомендований workflow

- Тримайте прикладні проєкти окремо від бібліотеки.
- Тримайте `pic-platform` зовнішнім і спільним для різних проєктів.
- Не модифікуйте драйвери під кожен проєкт; налаштовуйте лише конфігурацію проєкту.
